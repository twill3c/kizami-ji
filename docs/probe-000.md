# probe-000 — 先行検証(リポジトリ作成前)

実施 2026-08-29。スクリプトは `probe/` に取り込んである。
**ここの数値はすべて probe 由来であり、本流実装で再現するまで「未再現」である**(onomato-atlas HC-001)。

## 何を確かめたかったか

SPEC に閾値を書く前に、三つ潰しておきたかった。

1. IPADIC を**自前で組み直せるか**(配布量が現実的か)
2. 参照実装(MeCab)を一切見ない独立実装が、**コストまで厳密に一致しうるか**
3. 一致しないとしたら、その原因は何か

## 環境

- `ipadic` 1.0.0(mecab-ipadic 2.7.0-20070801)。`pip install ipadic` で導入
- `fugashi`(既存の `juchu-desk/.venv` にあったものを流用)
- コーパス: `../aozora-sakuin/data/normalized`(5,000 作)

`fugashi` に `-d` / `-r` を渡すときは **Windows パスのバックスラッシュを `/` に置換する**
(MeCab がエスケープとして食う)。`ipadic` の dicdir には `mecabrc` が無いので、空の `mecabrc` を
`-r` で渡す必要がある。

`sys.dic` ヘッダ: `lexsize` 392,126 / `lsize` 1,316 / `rsize` 1,316 / charset utf8。内訳は

## double-array の全走査

`sys.dic` の double-array を DFS で全走査し、表層を復元した(`probe/da_enum` 相当のコードは
`probe/ref.py` の `cps` に集約してある)。

- 表層 **325,871 種**
- 復元したトークン総数 **392,126** = ヘッダの `lexsize` と一致

**この一致が件数オラクルになる**(HC-012)。表層の復元に取りこぼしがあれば総数が合わない。

darts の `check` は親ノードの添字ではなく**親の `base` 値**を保持する。ここを取り違えると
走査が静かに空を返す。

## 文字種(char.bin)

11 カテゴリを復元: DEFAULT / SPACE / KANJI / SYMBOL / NUMERIC / ALPHA / HIRAGANA /
KATAKANA / KANJINUMERIC / GREEK / CYRILLIC。

`invoke` / `group` / `length` は IPADIC 同梱の `char.def` と値まで一致した。

| 文字種 | invoke | group | length |
|---|---|---|---|
| KATAKANA | 1 | 1 | 2 |
| HIRAGANA | 0 | 1 | 2 |
| KANJI | 0 | 0 | 2 |
| ALPHA / NUMERIC / SYMBOL | 1 | 1 | 0 |
| SPACE / DEFAULT | 0 | 1 | 0 |

ビットフィールドの詰め方は type 18 bit / default_type 8 bit / length 4 bit / group 1 bit / invoke 1 bit。
マップは 0xFFFF 要素(BMP のみ)。

## 照合の結果

### 未知語生成を入れる前

3,000 文で、辞書語だけを使った Viterbi は **1,969 / 1,997 一致(98.60%)**、
1,003 文は経路なし。不一致 28 件は**全部がカタカナ語のまとめ上げ**だった
(`ラ/ロ` 対 `ラロ`、`ス/ウェア` 対 `スウェア`、`バタ/アン` 対 `バタアン`)。

### 未知語生成を入れた後

青空文庫 400 作から抽出した **10,000 文**(乱数種 20260829、4〜120 字):

| 測ったもの | 結果 |
|---|---|
| 総コストの不一致 | **0 / 10,000** |
| 分割の不一致 | 7 / 10,000 |
| うち完全同点 | **7 / 7** |
| 経路が見つからなかった文 | 0 |

**不一致の全部が「同じ最小コストに到達したうえで、どちらに倒すかが違う」だった。**

## 同点の実例

`probe/nbest.py` は短い文の全経路を列挙してコストを分解する。「の北詰まで」全 1,975 経路の上位:

```
12965  の(生+4816/連+934)  北(生+5058/連-2305)  詰(生+5665/連+62)  まで(生+1782/連-3789)
12965  の(生+4816/連+934)  北詰(生+7620/連-2166)              まで(生+1782/連-763)
13403  の(生+4816/連+934)  北(生+5058/連-2305)  詰(生+6103/連+62)  まで(生+1782/連-3789)
```

| 道 | Σ生起 | Σ連接 | EOS | 総計 |
|---|---|---|---|---|
| の / 北詰 / まで | 14,218 | −1,995 | +742 | 12,965 |
| の / 北 / 詰 / まで | 17,321 | −5,098 | +742 | 12,965 |

`北詰` を一語で持つぶん上の道は生起コストが 3,103 安く、下の道は連接コストがちょうど 3,103 安い。
出典は永井荷風「地下鉄道は既に京橋の北詰まで開鑿せられ」。

他に確認した同点: `通り/かかっ` 対 `通りかかっ`(133,717)、`どう/か` 対 `どうか`(67,016)、
`以爲/侈` 対 `以/爲侈`(37,706)、`ああ/あ` 対 `あ/ああ`(14,467)。

## SPEC への反映

この検証が SPEC を一つ変えた。詳細は `HARNESS_CHANGELOG.md` HC-001。

- O-1 を **O-1a(総コスト)/ O-1b(分割・タイブレーク規則を合わせた上で)** に分割した
- 「δ = 0 が実在する」は仮説ではなく観測になった。ただし**測れるのは下限**である —
  二つの実装が同じ側に倒れた同点は、照合では見えない

## 再現方法

```
python probe/cmp.py     # 6 文の厳密照合
python probe/bulk2.py   # 10,000 文の照合(数分)
python probe/nbest.py   # 全経路列挙とコスト分解
python probe/charprop.py # char.bin の復元
```

`fugashi` と `ipadic` が入った Python が要る。`probe/` は**参照実装**であり、
出荷実装(TypeScript)はここを一切参照しない(O-2)。
